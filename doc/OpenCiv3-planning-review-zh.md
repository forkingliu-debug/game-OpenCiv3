# OpenCiv3 策划视角项目评估

## 1. 文档目的

这份文档不是源码导读，而是站在策划、系统设计、项目评估的视角，回答这些问题：

- 这个项目现在总体做到了什么程度
- 已经包含了哪些核心系统
- 各系统大概是怎样组织和运作的
- 数值框架是否已经成型
- 哪些内容已经能支撑玩法，哪些还只是半成品
- 如果把它当作一个可继续开发的 4X 项目，策划下一步该关注什么

## 2. 总体结论

OpenCiv3 当前更像一个“有明确规则骨架和内容承载能力的 pre-alpha 开源 4X 项目”，而不是一个只做了界面的技术 Demo。

从策划角度看，它已经具备以下几个比较关键的基础：

- 有完整的 4X 基本盘
  - 地图、城市、单位、科技、政府、资源、生产、回合推进、外交基础、AI、野蛮人
- 有明显继承自 Civilization III 的规则体系
  - 科技树、政府差异、腐败、奢侈品、资源前置、人口增长、文化扩张等
- 有可扩展的规则承载方式
  - C# 核心逻辑 + Lua 规则扩展 + JSON 规则数据
- 有原版 Civ3 内容兼容能力
  - 规则、地图、存档、原始素材

但同时，它距离“策划可以稳定往上叠内容、做平衡迭代”的成熟阶段还有明显差距。核心问题不是基础系统不存在，而是：

- 仍有不少系统是“部分实现”
- 很多后期系统和胜利系统尚未闭环
- 若干子系统虽然有数据或入口，但玩法深度不足
- 文档与工程版本有一定脱节，工具链也不够收敛

所以更准确的定位应该是：

- 适合研究和继续扩建的系统底盘
- 不适合作为已经完整可运营的 4X 成品框架

## 3. 适合策划理解的项目画像

这个项目最像什么？

它像一个以《文明3》规则传统为基础、但准备逐步现代化改造的开源 4X 框架。它不是完全重新发明设计，也不是机械复刻原版，而是在做三件事：

- 保留 Civ3 的核心乐趣结构
- 用新的工程方式重建系统
- 给未来模组化和规则扩展留空间

对策划来说，这意味着它的价值不只是“能跑一局”，而是：

- 已经有相当多可调参数
- 已经有较完整的数据资产结构
- 已经能承载体系化规则设计
- 但还需要大量“玩法闭环策划”与“内容落地策划”

## 4. 当前已有系统总览

下面按策划最关心的游戏系统维度来看。

### 4.1 世界与地图系统

当前状态：较完整，已经具备玩法骨架。

已包含内容：

- 世界尺寸
- 海洋覆盖率
- 气候、温度、地质年代
- 大陆形态
- 地图包裹
- 地形类型
- 河流
- 山地/丘陵
- 生物群系
- 奖励资源、战略资源、奢侈资源
- 开局出生点选择
- 野蛮人营地分布

特点：

- 地图生成不是占位逻辑，而是一整套规则驱动生成流程
- 已经在考虑平衡性，例如：
  - 大陆大小
  - 奢侈品分布
  - 起始点间距
  - 小岛承载能力

策划价值：

- 已经足以支撑“地图体验”和“开局差异”
- 可以继续在此基础上做更精细的地图主题、开局脚本、文明偏好和场景设计

主要缺口：

- 更多场景化地图脚本
- 更清晰的地图目标体验定义
- 海战/运输/后期跨海战略尚不成熟，限制了地图系统的后期表达力

### 4.2 文明与玩家系统

当前状态：基础完整。

已包含内容：

- 文明定义
- 文明特性
- 城市名列表
- 领袖信息
- 主副色
- 特色单位替换链
- 开局文明选择
- 难度与 AI 开局补偿

说明：

- 文明不是纯皮肤层，已经会影响：
  - 起始科技
  - 单位替换
  - 建筑折扣
  - AI/扩张相关判断

策划价值：

- 文明差异化已经有制度接口
- 未来很适合做“文明包”“mod ruleset”“历史场景阵营”

主要缺口：

- 文明特性的玩法反馈还不够厚
- 文明特色更多仍停留在 Civ3 传统结构，没有明显新设计拓展

### 4.3 城市系统

当前状态：较完整，是目前最有可玩性的系统之一。

已包含内容：

- 建城
- 城市人口
- 市民工作地块
- 食物增长
- 饥荒减员
- 生产积累
- 生产完成
- 建筑完成
- 单位训练
- 文化累计
- 边界扩张
- 城市等级上限
- 粮仓逻辑
- 水源/引水渠/医院对成长上限的限制
- 腐败
- 民情快乐/不满
- 军事警察
- 奢侈品幸福
- 强征/花钱催产
- 城市维护费

说明：

- 城市已经不是“显示一个数值盒子”，而是真正的经济核心
- 产出分为：
  - 食物
  - 盾
  - 商业
- 商业还会再拆成：
  - 税收
  - 科研
  - 娱乐
  - 腐败损失

策划价值：

- 这部分已经足够承载中前期经营玩法
- 是当前最适合继续加内容和平衡的区域

主要缺口：

- 城市专精和建筑联动深度还不够
- 缺少更多城市事件、区域差异、成长决策张力
- 部分高级城市场景的系统反馈还偏薄

### 4.4 地块与资源系统

当前状态：较完整。

已包含内容：

- 地块基础产出
- 政体对地块产出的修正
- 道路、铁路、灌溉、矿山等改良
- 地块可用资源限制
- 奢侈、战略、奖励资源分类
- 贸易网络下的资源可达性

说明：

- 资源已经会真实影响生产条件和城市幸福
- 地图资源分布与城市经营、外交交易、扩张路径是连在一起的

策划价值：

- 资源系统已经可以支撑“扩张为了资源”的核心 4X 动机

主要缺口：

- 港口/机场等更复杂贸易网络节点仍未完全处理
- 资源争夺的中后期戏剧性还有限

### 4.5 单位与战斗系统

当前状态：基础可用，但还未达到完整战棋深度。

已包含内容：

- 单位原型
- 攻击/防御/轰炸/移动
- 近战战斗
- 防御轰炸
- 单位经验等级
- 升级链
- 城市防御加成
- 工人地改
- 建城单位
- 自动探索/自动化/驻守/待机等基础动作

说明：

- 战斗并不是空壳，已经有比较明确的数据结构和计算流程
- 轰炸存在，但相关 UI 与 AI 表现尚不完全成熟
- 海军、运输、空军等更复杂兵种体系还未形成完整玩法闭环

策划价值：

- 足以支撑陆地中前期冲突
- 不足以支撑完整的全时代兵种博弈体验

主要缺口：

- 海战与运输体系不完整
- 空军/机场/航母等链条不完整
- 征兵、战争疲劳等高级军政系统未完成
- 自动轰炸、专业化兵种控制等前端操作支持不足

### 4.6 科技系统

当前状态：较完整。

已包含内容：

- 科技树
- 前置科技关系
- 时代划分
- 科技成本
- 科研队列
- 研究进度
- 时代推进
- 首发奖励科技
- 科技顾问 UI

说明：

- 科技系统已经有清晰的“可研究集合”逻辑
- 科技成本已参考 Civ3 公式，并考虑：
  - 地图规模
  - 难度
  - 已知文明掌握数
  - 当前科技进度

策划价值：

- 这是当前最稳定的数值系统之一
- 很适合继续做节奏、时代体验和文明差异化调优

主要缺口：

- AI 科技偏好仍较基础
- 科技所驱动的中后期系统，有些本身还未完全实现

### 4.7 政体与国家运营系统

当前状态：较完整。

已包含内容：

- 多种政府类型
- 政体切换
- 无政府期
- 腐败模型差异
- 军事警察上限
- 催产方式差异
- 单位维护差异
- 工人效率
- 地块产出修正

说明：

- 政体不是纯文本标签，而是影响：
  - 城市产出
  - 腐败
  - 幸福
  - 军队维持
  - 研发和经济效率

策划价值：

- 已经具备相当明确的“国家经济模型分化”
- 适合继续做政体风格与战略路线区分

主要缺口：

- 战争疲劳等关键政体差异尚未完整加入
- 部分政体策略价值还未通过完整玩法生态体现出来

### 4.8 外交系统

当前状态：已做出基础框架，但深度仍有限。

已包含内容：

- 初次接触
- 和平/战争状态
- 和平条约
- 拒绝接触时间
- 贸易报价 UI
- 金钱、科技等交易
- 多回合协议数据结构
- 通行权、联盟、禁运等类型定义

说明：

- 外交并非完全缺失，底层关系模型已经建立
- 多回合 Deal 的建模是比较重要的一步，说明系统方向是对的
- 但 UI、规则、AI、后果系统尚未完全丰满

策划价值：

- 已经可以作为未来外交扩展的底盘
- 但还不足以支撑“外交驱动胜利”或高层次国际博弈

主要缺口：

- 许多协议只是类型存在，玩法未完整兑现
- 信誉、长期外交记忆、谈判层次仍较弱
- 外交目标、第三方关系博弈还不强

### 4.9 文化系统

当前状态：基础存在，但还比较薄。

已包含内容：

- 建筑文化产出
- 城市总文化
- 文化扩边
- 文化导致边界变化

说明：

- 文化最明确的现有效果是领土扩张
- 文化在城市/边境竞争中已有实际功能

主要缺口：

- 文化胜利目标未见完整实现
- 文化翻城、文化压力等复杂玩法未见成型
- 文化系统目前更像边界系统的一部分，而不是独立胜利路线

### 4.10 经济系统

当前状态：较完整。

已包含内容：

- 金币收支
- 城市维护
- 单位支持费
- 腐败
- 贸易收入/支出
- 利息类奇观效果
- 财富型生产
- 科研/娱乐/税率三滑条

说明：

- 已经有一套比较像 Civ3 的国家级收支模型
- 玩家需要在：
  - 现金流
  - 科研速度
  - 民情稳定
  - 军费支出
 之间权衡

策划价值：

- 这是一个成熟度较高的中观经济框架

主要缺口：

- 经济系统与胜利系统、外交系统、后期内容的联动还不够强

### 4.11 AI 系统

当前状态：基础较强，但仍偏“可用引擎 AI”而非高水平成品 AI。

已包含内容：

- 玩家 AI
- 野蛮人 AI
- 扩张优先级
- 战争优先级
- 定居点选址
- 单位寻路
- 工人/移民/探索/防守/战斗 AI
- 城市生产选择
- 城市地块分配

说明：

- 这套 AI 已经能支撑基本局面演化
- 不是“假 AI”，而是真正做决策的系统

策划价值：

- 足以支撑单机测试和规则验证
- 还不适合拿来做高质量 AI 卖点

主要缺口：

- 海战、运输、后期科技与复杂外交相关 AI 还不成熟
- 缺少更高级别的战略人格和局势应对层

### 4.12 UI / 顾问 / 信息展示系统

当前状态：功能覆盖面不错，但仍是 pre-alpha 质感。

已包含内容：

- 主菜单
- 新游戏流程
- 快速开始
- 加载游戏 / 加载场景
- 城市界面
- 科技顾问
- 军事顾问
- 内政顾问
- 外交界面
- 宫殿界面
- 右键菜单
- 信息弹窗
- 地图层展示

说明：

- UI 覆盖了 Civ3 的主要交互结构
- 但很多地方更像“功能存在”，还没到精细化打磨阶段

主要缺口：

- 若要面向更广泛玩家，仍需大量 UX 整理
- 很多复杂系统的可解释性和反馈强度有待提升

## 5. 数值框架是否已经成型

结论：已经有明显成型的数值骨架，但还没有进入完整平衡阶段。

### 5.1 已成型的数值骨架

当前已能看到完整数值链路的模块包括：

- 单位战斗数值
  - 攻、防、轰炸、移动、人口成本、盾成本、资源前置、科技前置
- 城市产出数值
  - 食物、盾、商业、腐败、维护费、文化
- 科技数值
  - 科技成本、前置链、时代推进、首发奖励
- 政体数值
  - 腐败、催产方式、军警上限、单位维护、工人效率、地块修正
- 难度数值
  - AI 开局补偿、AI 费用折扣、出生满意人口、额外免费维护等
- 地图数值
  - 地图大小、科技速率、最优城市数、资源出现率、出生点间距

### 5.2 数值框架的特点

它现在更偏“经典 Civ3 逻辑数值骨架”，不是现代数值表驱动全面重构。

优点：

- 结构稳定
- 参考系明确
- 容易复用原版经验
- 易于导入和兼容 Civ3 内容

缺点：

- 创新空间暂时更多在局部规则和内容层，而不是根本设计框架
- 若要做显著区别于 Civ3 的新体验，需要在中后期系统和胜利系统上继续扩张

### 5.3 数值层目前最适合策划发力的方向

- 建筑价值曲线梳理
- 科技节奏和时代节奏
- 政体差异强化
- 资源稀缺度和贸易价值
- 文明特性价值感
- 生产与成长曲线
- 幸福/腐败/军费的国家经营张力

## 6. 目前缺失或不完整的关键内容

这是策划最需要注意的部分。

### 6.1 胜利系统明显不完整

从当前代码结构看，没有看到完整闭环的胜利判定系统，例如：

- 统治胜利
- 文化胜利
- 外交胜利
- 太空竞赛
- 分数结算

这意味着：

- 项目现在更像“能跑局”的系统沙盘
- 还不是“完整对局目标闭环”的成品策略游戏

### 6.2 后期系统和全时代完整性不足

虽然数据里已有大量后期科技和单位，但从实现程度看，后期玩法链条并不完整，例如：

- 空军体系
- 机场/航母/空运完整闭环
- 海运投送
- 更复杂的海军对抗
- 后期全球战略工具

### 6.3 外交深度不足

现有外交更像“基础交易与战争关系系统”，还不是完整外交博弈游戏。

缺少或偏弱的点包括：

- 外交人格与长期记忆
- 声望系统
- 复杂谈判
- 第三方博弈
- 外交胜利支撑结构

### 6.4 一些经典 Civ3 机制仍在 TODO 阶段

代码里能直接看到一些明确未完成的内容，例如：

- 战争疲劳
- 征兵惩罚
- 更完整的奇观全局效果
- 更完整的贸易网络节点
- 部分地改/设施效果

### 6.5 多人联机不是当前成熟方向

代码里有“未来也许便于联网”的思路，但没有看到成熟多人玩法框架。

对策划来说，这意味着：

- 当前应视为单机/观察模式优先
- 不宜把多人作为近期玩法核心卖点

## 7. 如果给策划做系统成熟度分级

我会这样分：

### A 级：已有明显玩法承载力

- 地图生成
- 城市经营
- 基础经济
- 科技推进
- 政体差异
- 资源系统
- 基础 AI

### B 级：已有结构，但还需大量玩法打磨

- 单位战斗
- 外交
- 建筑系统
- 文化系统
- 顾问/辅助界面
- 文明差异化

### C 级：有数据或入口，但未形成完整产品级玩法

- 胜利系统
- 后期全时代玩法闭环
- 海空军完整生态
- 多人
- 高级国际博弈
- 后期宏观目标与结算反馈

## 8. 这个项目最适合哪类策划继续推进

最适合的不是纯剧情策划，也不是只做 UI 文案的人，而是下面几类：

- 4X 系统策划
  - 能看懂科技、城市、资源、政体、外交之间的联动
- 数值策划
  - 能建立中长期平衡框架
- 规则策划 / 模组策划
  - 能利用现有 JSON + Lua 扩展体系
- 内容策划
  - 补足文明包、规则包、历史场景、建筑与奇观体验

## 9. 如果要把它继续做下去，策划上最值得投入的方向

### 方向一：把“完整对局闭环”补出来

优先项：

- 胜利条件体系
- 中后期目标感
- 结算与局势判断
- AI 与胜利目标联动

这是最能把项目从“能玩”推到“成局”的方向。

### 方向二：把外交和国际关系做成真正的博弈层

优先项：

- 外交协议落地
- 信誉与违约代价
- 第三方联盟与禁运
- AI 外交人格

这会明显提升中盘和后期的局势复杂度。

### 方向三：强化文明差异和政体差异

优先项：

- 文明特性更强反馈
- 专属节奏
- 政体战略身份感
- 建筑/资源/单位联动

这会让每局体验差异更鲜明。

### 方向四：把后期内容做厚

优先项：

- 海空军完整玩法
- 后期地改和设施
- 现代与未来时代目标
- 大型奇观与项目系统

这会让时代跨度真正完整。

## 10. 对项目风险的策划判断

### 10.1 优势

- 底层分层清楚
- 已有大量核心系统
- 原版 Civ3 内容可借力
- 规则与数据已有承载方式
- 适合长期演进

### 10.2 风险

- 文档与工程状态存在不一致
- 很多系统是“有骨架但未打磨”
- 若没有明确策划路线，容易长期停在技术性可玩阶段
- 如果盲目扩内容而不先补闭环，会越做越散

## 11. 作为策划该怎么使用这个项目

如果你要基于它继续研究或设计，我建议不要把它当成“已经成熟可直接加内容的完整产品”，而要把它当成：

- 一套强骨架的 4X 基础工程
- 一份相对先进的 Civ3 规则重建样本
- 一个适合继续补全、打磨、定义方向的中早期项目

更具体地说：

- 如果你的目标是研究 4X 规则组织方式，它很有价值
- 如果你的目标是快速做一个 Civ3-like 原型，它也很有价值
- 如果你的目标是直接把它当成成熟 commercial framework，则还不够

## 12. 最后结论

从策划视角看，OpenCiv3 当前最重要的事实不是“它做了多少界面”，而是：

- 它已经有一套能承载 4X 策略游戏的系统底盘
- 其中城市、科技、政体、地图、经济这几块已经比较像样
- 外交、文化、后期体系、胜利体系仍需要大量补全
- 它现在最需要的不是继续零散加功能，而是明确玩法闭环和阶段目标

如果用一句话总结这份评估：

这不是一个完成度很高的 Civilization III 成品替代品，但它已经是一套值得认真接手、继续做成真正 4X 游戏的系统框架。
